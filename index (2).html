    Concepts

    The three ideas behind every pipeline diagram.

    Stages

    IF reads the instruction at the program counter.

    ID decodes it and reads the source registers.

    EX runs the ALU or computes a memory address.

    MEM loads or stores data. WB writes the result to a register.

    Once full, the pipeline completes one instruction per cycle. Total time for n instructions is n + 4 cycles.

    Hazards

    Structural: two instructions need the same hardware in the same cycle, such as one memory port for fetch and data.

    Data: an instruction needs a result an earlier instruction has not written yet (read after write).

    Control: a branch changes the program counter, so the instructions fetched after it may be wrong.

    Stalls and fixes

    Stall: hold an instruction in ID and insert bubbles until its operands are ready.

    Forwarding: send a result straight from the EX or MEM stage back to the ALU input. It removes most data stalls.

    Load-use: a load’s value only exists after MEM, so even with forwarding the next instruction waits one cycle.

    Branches: predict not taken, or stall until the branch resolves in EX.
